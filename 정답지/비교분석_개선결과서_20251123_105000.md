# sampleSrc 메타DB 생성 품질 개선 결과서 (2025-11-23 10:50:00)

## 개선 목표
- **누락 없는 대략적 분석**을 우선시하여, 소스의 실제 파일 경로/ID를 메타DB에 정확히 남기고 `inferred/*.inferred` 가짜 파일 매핑을 최소화한다.
- `main.py` 실행만으로 메타DB가 올바르게 생성되도록 초기화/파싱 흐름을 정리한다.

## 현황 요약
- `files` 테이블이 `inferred/INVENTORY_AUDIT.inferred`로 오염되며 실제 XML/JAVA 파일 경로가 사라짐.
- 원인: 파싱 단계에서 `file_id` 전달 실패 → `_resolve_or_create_file_id`가 실패하고 inferred 파일을 생성. 또한 이미 열린 커넥션 상태에서 DB 삭제를 재시도하며 잠금/재생성 문제가 동반.

## 적용한 수정
1. **DB 초기화 순서 정리**  
   - `main.py`: `--clear-metadb` 시 메타DB·SqlContent.db를 DB 연결 전에만 삭제하도록 변경.  
   - `file_loading.py`: 이미 열린 커넥션 상태에서는 삭제를 건너뛰도록 보호(잠금 경고 차단).

## 추가 개선안(적용 예정)
1. **파일 컨텍스트 유지 전역 관리**  
   - 로딩 엔진 공통 컨텍스트(예: `FileContext`)에 `current_file_id`, `file_path`, `file_name`을 저장하고, XML/Java 파서→`SqlContentManager.save_sql_content` 호출 시 반드시 전달.  
   - `SqlContentManager`에서 `file_id` 보정 실패 시 inferred 생성 전에 경고 후 재탐색(경로 유사 매칭)하고, 마지막 수단으로만 inferred 생성.
2. **`files` 테이블 보호**  
   - 스캔 이후 `files`를 쓰는 모듈을 `file_loading`으로 한정. 다른 모듈은 읽기 전용으로 하고, inferred 추가 시 기존 정상 파일을 건드리지 않도록 `INSERT OR IGNORE` 방식으로 제한.
3. **가드/검증**  
   - 1단계 직후 `files`에 XML/JAVA/JSP 등이 존재하지 않으면 즉시 실패 처리.  
   - 비교/리포트 시 `file_type='INFERRED'`를 기본 제외하여 노이즈 차단.

## 기대 효과
- SQL 컴포넌트가 실제 소스 파일(`*.xml`, `*.java`)의 `file_id`에 매핑되어 경로 유실 없이 메타DB가 생성됨.
- 잠금/재초기화로 인한 `files` 테이블 초기화 문제 해소.

## 요청 사항
- 위 추가 개선안을 적용해도 되는지 확인 부탁드립니다. 승인 시 컨텍스트 저장/파서 전달/guard 로직을 구현하고 재검증 리포트를 제공하겠습니다.
