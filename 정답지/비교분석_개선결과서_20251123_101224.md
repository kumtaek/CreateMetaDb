# 비교분석 개선결과서 (2025-11-23 10:12:24)

## 개선 배경
- `비교분석서_20251122_204817.md`에서 확인된 핵심 문제: SQL 컴포넌트가 모두 `INVENTORY_AUDIT.inferred`로 매핑되고 `files` 테이블에 XML 등이 등록되지 않아 소스 경로가 유실됨.
- 원인: `util/sql_content_manager.py`가 `file_id` 미지정/불일치 시 무조건 1번 파일로 대체하면서 실제 파일 메타와 연결이 끊어짐.

## 수정 사항
- 대상 파일: `util/sql_content_manager.py`
- 주요 변경
  - `file_id`가 비거나 유효하지 않을 때 경로/파일명으로 재검색 후 매칭, 실패 시 자동으로 파일 메타를 생성하도록 `_resolve_or_create_file_id` 추가.
  - 경로는 `PathUtils.normalize_path_separator(..., 'unix')`로 크로스플랫폼 정규화, 파일 타입은 `FileUtils.get_file_type` 기반으로 저장.
  - `file_id`를 찾지 못하면 더 이상 1번 파일로 강제 매핑하지 않고 오류로 처리하여 잘못된 관계 저장을 차단.
  - `save_sql_content` → `_register_sql_component` 호출 시 `file_name`을 전달하도록 보강해 경로 매핑 안정화.

## 기대 효과
- MyBatis/JPA/Java 문자열 SQL 컴포넌트가 실제 소스 파일(`files` 테이블)과 정확히 연결되어 `components.file_id`가 올바르게 채워짐.
- `SqlContent.db`의 `file_path` 정보를 활용해 누락된 파일 메타가 자동 생성되므로 XML 미등록 문제를 완화.
- 이후 `USE_TABLE`/리포트 등 관계 역추적 시 `inferred` 가짜 파일로 묶이는 현상 방지.

## 후속 권고
- 메타DB를 다시 생성해 정합성을 검증: `python main.py --project-name sampleSrc --clear-metadb`.
- 재생성 후 `files`에 XML/리포지토리/DAO 파일이 정상 등록되었는지, `components`의 `file_id`가 실제 경로를 가리키는지 점검.
- JPA 컴포넌트명 `_Qry_n` 접미사 및 정답지 미포함 SQL 목록은 별도 정책을 정해 정답지/파서 로직을 일치시킬 것.
