# 백엔드 매핑표 vs 메타DB 비교 분석 (2025-11-22 14:27:58)

## 요약
- 비교 대상: `정답지/정답지_백엔드_매핑표.md` vs `projects/sampleSrc/metadata.db` (`components` 기준).
- 결과: 메타DB는 실제 `sampleSrc` 파일들의 쿼리를 충실히 수집하고 있으나, 정답지에 누락/오기재가 많음. 메타DB 쪽 품질 문제는 확인되지 않음.

## 상세 비교

### 1) MyBatis 매핑 (mapper XML)
- 메타DB: 51건 (`src/main/resources/mybatis/mapper/*.xml`), 모두 XML의 `<select|insert|update|delete>` id와 일치.
- 정답지: 41건만 수록. 실제 없는 항목 20건을 잘못 기재했고, 실제 존재하는 31건 누락.
- 근거
  - 실제 ID 목록 예시: `selectUsersWithOrderDetails`, `selectUsersWithOrderStatistics`, `selectUsersWithRecentOrders`, `selectUsersWithActiveOrders`, `getUserStatisticsByStatus`, `getMonthlyRegistrationStats`, `insertProductDynamic`, `deleteProductsByCondition`, `existsByUsername`, `isEmailVerified` 등.
  - 잘못 기재된 항목(메타DB·XML에 없음): `findUsersByUsername`, `findUsersByEmail`, `findUsersByStatus`, `findUsersByUserType`, `findUsersByCreatedDate`, `findUsersByLastLoginDate`, `findUsersByAgeRange`, `findUsersByLocation`, `findUsersByPreferences`, `findUsersByActivity`, `insertProduct`, `selectProductsByPriceRange`, `selectProductsByStatus`, `selectProductsByStockLevel`, `selectProductsByCreatedDate`, `selectProductsWithCategories`, `selectOrdersWithUsers`, `softDeleteUser`, `updateUserLastLogin`.
  - 확인 파일: `projects/sampleSrc/src/main/resources/mybatis/mapper/UserMapper.xml`, `ProductMapper.xml`, `UserManagementMapper.xml`, `ImplicitJoinMapper.xml`, `MergeQueryMapper.xml`.
- 원인/개선: 정답지가 오래되었거나 가공된 예시를 포함. 정답지의 MyBatis 섹션을 XML ID 51건으로 갱신해야 함. 메타DB는 정상.

### 2) JPA Repository (@Query/파생 쿼리 포함)
- 메타DB: 86건 (`src/main/java/com/example/jpa/repository/*.java`의 @Query 및 파생 쿼리 명을 `_Qry_1` 등으로 수집). 예: `OrderRepository.findByOrderStatusWithUser`, `findOrdersContainingProductsFromCategory`, `findOrdersByDynamicCriteria`, `findRecentOrdersByStatuses`, `ProductRepository.findProductsInActiveCategories`, `CategoryRepository.getActiveCategoriesWithProductCount`, `UserRepository.findActiveUsersFromDate`, `JoinConditionRepository.*`, `MergeQueryRepository.*` 등.
- 정답지: 20건만 수록(대부분 native 쿼리). 메타DB 대비 66건 누락, 잘못된 추가 기재는 없음.
- 확인 파일: `projects/sampleSrc/src/main/java/com/example/jpa/repository/OrderRepository.java`, `ProductRepository.java`, `CategoryRepository.java`, `UserRepository.java`, `JoinConditionRepository.java`, `MergeQueryRepository.java`.
- 원인/개선: 정답지가 native 일부만 담아 전체 검증용으로 부족. 정답지에 JPQL/파생 쿼리를 포함하거나, 검증 범위를 “native 한정”으로 명시해야 일관된 비교가 가능. 메타DB는 해당 파일들의 쿼리를 모두 수집하고 있어 정상.

### 3) Java 문자열 기반 SQL (DAO 직접 실행)
- 메타DB: 12건 (`src/main/java/com/example/dao/*.java`), `CoreSqlPatternDao.executeOracleDataWarehouseQuery` 포함.
- 정답지: 11건(위 메서드 누락). 기타 항목은 메타DB와 일치.
- 확인 파일: `projects/sampleSrc/src/main/java/com/example/dao/CoreSqlPatternDao.java`(Oracle DW implicit join/윈도우 함수), `MergeQueryDao.java`, `JoinQueryDao.java`.
- 원인/개선: 정답지 누락. `executeOracleDataWarehouseQuery` 항목 추가 필요. 메타DB는 정상.

## 결론 및 개선 제안
- 차이 원인: 모두 `정답지/정답지_백엔드_매핑표.md`의 누락·오류. 메타DB는 `sampleSrc` 실제 쿼리와 일치함을 파일 단에서 확인.
- 개선 방안
  1) MyBatis: XML ID 51건으로 정답지 전체 갱신(불필요 항목 제거 후 실제 ID 추가).
  2) JPA: 정답지 범위를 명확히(전체 @Query/파생 쿼리 포함 또는 native 한정 명시)하고, 메타DB 수준으로 목록 보강.
  3) Java 문자열 SQL: `executeOracleDataWarehouseQuery` 추가로 정답지 보완.
- 검증 포인트: 메타DB `components` 테이블은 `file_path`별로 SQL_* 타입을 모두 보유함 (`projects/sampleSrc/metadata.db` 확인). 정답지 수정 후 다시 비교하면 일치해야 함.
