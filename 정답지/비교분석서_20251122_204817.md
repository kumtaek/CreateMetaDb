## 공통 관찰
- `SELECT DISTINCT f.file_path FROM components c JOIN files f ON c.file_id=f.file_id` 결과가 `inferred` 한 값뿐이며 `files` 테이블에 `*.xml` 레코드가 0건이라 모든 SQL 컴포넌트가 가짜 파일(`INVENTORY_AUDIT.inferred`)을 가리킴.
- `SqlContent.db`에는 `file_path`가 정상 보존됨(예: `src/main/resources/mybatis/mapper/ImplicitJoinMapper.xml`의 `selectUsersWithOrders`), 따라서 추출 단계는 성공했으나 메타DB 적재 시 파일 매핑이 끊어진 상태.
- 이로 인해 리포트/관계 추적 시 소스 파일 단위의 정합성 검증이 불가능하며, 누락/오탐을 일으킴.

## MyBatis SQL 매핑
- 현황: 정답지 51건 대비 메타DB 기록 19건, 그중 정답지와 일치 7건(ProductMapper 일부), 누락 44건.
- 누락 묶음: `ImplicitJoinMapper` 5건, `MergeQueryMapper` 5건, `UserManagementMapper` 6건, `UserMapper` 21건, `ProductMapper` 7건. 해당 쿼리는 실제 소스(`projects/sampleSrc/src/main/resources/mybatis/mapper/*.xml`)와 `SqlContent.db`에 존재함.
- 메타DB 추가(정답지 미수록): `src/com/example/dynamicquery/UserMapper.xml` 계열 11건 등 총 12건이 기록되어 있어 대상 파일 선정이 어긋난 정황.
- 원인: `files` 테이블에 MyBatis XML이 전혀 등록되지 않아 `xml_loading` 결과가 모두 `inferred` 파일로 삽입됨. `FileLoadingEngine`는 `include_patterns`에 XML이 있지만 등록이 되지 않아 파일 스캔/ID 매핑 로직이 실패한 것으로 보임.
- 개선: `files` 테이블에 `src/main/resources/mybatis/mapper/*.xml`을 정상 등록하도록 스캔 경로 및 파일 타입 판정 로직을 재검증하고, `sql_contents.file_path`를 `PathUtils.normalize_path_separator(...,'unix')`로 정규화하여 존재하지 않는 파일이면 생성 후 `file_id`를 연결해야 함. 수정 후 `python main.py --project-name sampleSrc --clear-metadb`로 재생성 필요.
