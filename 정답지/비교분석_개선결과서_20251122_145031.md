## 개선 내용

### 1. SQL_QUERY 타입 분류 개선 (핵심 개선)
**문제점**: Java Service에서 MyBatis Mapper를 호출할 때, SQL 내용이 없는 INFERRED 쿼리가 `SQL_QUERY` 타입으로 저장됨.

**해결 방안**: 메서드명에서 SQL 타입을 추론하는 로직 추가

**수정 파일**:
1. `java_loading.py`
   - `_infer_sql_type_from_method_name()` 메서드 추가
   - INFERRED 쿼리 등록 시 메서드명 기반 타입 추론 적용

2. `util/sql_content_manager.py`
   - `_determine_sql_component_type()` 메서드 확장
   - SQL 내용이 없거나 타입을 결정할 수 없는 경우 `query_id`(메서드명)에서 추론

**추론 규칙**:
| 메서드명 접두어 | SQL 타입 |
|----------------|----------|
| select, find, get, count, exists, search, query, fetch, load, retrieve | SQL_SELECT |
| insert, create, add, save, register | SQL_INSERT |
| update, modify, change, edit, set | SQL_UPDATE |
| delete, remove, drop, truncate, erase | SQL_DELETE |
| merge | SQL_MERGE |

### 2. 코드 변경 상세

#### java_loading.py (라인 246-274)
```python
def _infer_sql_type_from_method_name(self, fqmn: str) -> str:
    """
    MyBatis Mapper 메서드명(FQMN)에서 SQL 타입을 추론.

    Args:
        fqmn: Fully Qualified Method Name (예: UserMapper.selectById)

    Returns:
        추론된 SQL 타입 (SQL_SELECT, SQL_INSERT, SQL_UPDATE, SQL_DELETE)
        추론 불가 시 SQL_QUERY 반환
    """
    method_name = fqmn.split('.')[-1] if '.' in fqmn else fqmn
    method_lower = method_name.lower()

    if method_lower.startswith(('select', 'find', 'get', 'count', ...)):
        return 'SQL_SELECT'
    elif method_lower.startswith(('insert', 'create', 'add', ...)):
        return 'SQL_INSERT'
    # ... 이하 생략
```
