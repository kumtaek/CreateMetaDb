# 신규 투입 개발자 스타트 가이드

## 1. 바로 이해해야 할 핵심 변화
- **INFERRED 파일/컴포넌트 자동생성 금지**: 원천 파일을 찾을 수 없으면 즉시 오류를 내고 중단한다.
- **전역 파일 컨텍스트 필수**: 분석을 시작한 파일 정보(file_id, path, type 등)를 `FileContext` 스택에 push/pop 하며, 미설정 상태에서 DB 기록을 시도하면 에러로 종료된다.
- **출처 보존**: SQL/컴포넌트/관계 저장 시 항상 실제 파일 `file_id`가 함께 저장된다. 임시(inferred) 파일명으로 대체하지 않는다.

## 2. 실행 흐름 요약 (main.py 기준)
1. **1단계 파일 스캔**: `file_loading.py`가 프로젝트 파일을 모두 등록. 이 단계에서 생성된 `file_id`를 이후 단계에서 재사용한다.
2. **2단계 DB 스키마 로드**: CSV 스키마를 metadata.db에 반영.
3. **3단계 XML(MyBatis) 분석**: 각 XML 파일 처리 시 `FileContext`에 push → SQL 컴포넌트 저장 시 해당 `file_id` 사용 → finally에서 pop.
4. **4단계 Java 분석**: Java 파일 처리 시 push/pop. 자바 문자열 SQL을 SqlContent.db에 저장할 때도 원본 `file_id`를 강제.
5. **5단계 백엔드 엔트리**: Spring/Servlet 매핑 분석 시 현재 파일 컨텍스트 필수.
6. **6단계 프론트엔드**: JSP/JS/TS 분석 시 파일 단위 push/pop. 관계 기록 시 컨텍스트 없으면 즉시 중단.
7. **7단계 일관성 검증**: 누락된 컴포넌트 없이 저장되었는지 검사.

## 3. 개발 시 체크리스트
- 새로운 파서/로더를 추가할 때:
  - 파일 시작 시 `FileContext.push_file(file_id, path, file_type, stage)` 호출.
  - 모든 기록 로직에서 `require_current_file()`로 컨텍스트를 강제.
  - 종료 시 `finally`에서 `pop_file()` 호출.
- DB 저장 유틸 사용 시:
  - `insert_or_replace_with_id` 호출 전에 컨텍스트가 존재하는지 확인.
  - 쿼리/테이블/관계 생성 시 `file_id` 전달 누락 여부 점검.
- 오류 대응:
  - "현재 파일 컨텍스트가 설정되지 않았습니다" 발생 시, 해당 스택 push 누락 여부를 로그로 역추적.
  - 파일을 찾지 못해 inferred 파일을 만들지 말고 즉시 예외를 발생시켜 원인을 수정한다.

## 4. 실행/디버깅 팁
- 기본 실행: `python main.py --project-name sampleSrc --verbose`
- 로그 위치: `logs/SourceAnalyzer_*.log`
- 실패 지점 재현: 에러 로그의 파일 경로를 따라가 `FileContext` push/pop 누락 여부 확인.
- 테스트: `pytest temp` (회귀), `pytest --maxfail=1 --disable-warnings -q` (스모크)
