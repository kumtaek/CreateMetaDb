# 신규 투입 개발자 스타트 가이드

## 문서 목적

이 문서는 SourceAnalyzer 프로젝트에 **신규 투입되는 개발자**가 빠르게 시스템을 이해하고 개발을 시작할 수 있도록 핵심 내용을 요약합니다.
**대상 독자**: 신규 투입 개발자, 유지보수 담당자
**참조 문서**: [01_시스템_요구사항_정의서.md](./01_시스템_요구사항_정의서.md), [03_처리_플로우_개요.md](./03_처리_플로우_개요.md)

## 1. 시스템 개요

**SourceAnalyzer**는 Java/Spring/MyBatis 기반 웹 애플리케이션의 소스코드를 분석하여 **프론트엔드 → 백엔드 → 데이터베이스**까지의 완전한 연관관계를 도출하는 메타데이터 분석 시스템입니다.

### 핵심 특징
- **9단계 분석 파이프라인**: 파일 스캔부터 일관성 검증까지 체계적 처리
- **듀얼 DB 아키텍처**: metadata.db (메타데이터) + SqlContent.db (압축 SQL)
- **FileContext 기반 추적**: 모든 컴포넌트가 원본 파일과 연결
- **INFERRED 생성 금지**: 파일을 찾을 수 없으면 즉시 오류 처리
- **sqltext 독립 관리**: SQL 파일을 독립적으로 관리하고 Java와 자동 매칭
- **9종 리포트 생성**: ERD, CallChain, Architecture, Mapping 등 다양한 리포트

## 2. 실행 명령어

### 기본 실행
```bash
# 가상환경 활성화
.\.venv\Scripts\activate

# 전체 분석 실행
python main.py --project-name sampleSrc

# 상세 로그 출력 (디버깅)
python main.py --project-name sampleSrc --verbose

# 메타DB 초기화 후 실행
python main.py --project-name sampleSrc --clear-metadb

# 설정 검증만 수행 (실제 분석 안 함)
python main.py --project-name sampleSrc --dry-run
```

### 리포트 생성
```bash
# 모든 리포트 생성
python create_report.py --project-name sampleSrc

# 특정 리포트만 생성
python create_report.py --project-name sampleSrc --report-type erd
python create_report.py --project-name sampleSrc --report-type callchain
python create_report.py --project-name sampleSrc --report-type backend-mapping

# 리포트 타입 목록
# callchain, erd, erd-dagre, erd-dagre-no-attribute,
# architecture, architecture-layer, sequence, query-list,
# backend-mapping, frontend-mapping, all
```

### 테스트 실행
```bash
# 회귀 테스트
pytest temp

# 스모크 테스트
pytest --maxfail=1 --disable-warnings -q

# 커버리지 확인
pytest --cov=. --cov-report=term-missing
```

## 3. 9단계 분석 파이프라인

| 단계 | 모듈 | 역할 |
|------|------|------|
| **1단계** | `file_loading.py` | 프로젝트 파일 스캔 → `files` 테이블 등록 |
| **2단계** | `file_loading.py` | CSV에서 DB 스키마 로드 → `tables`/`columns` 등록 |
| **2-1단계** | `sqltext_loading.py` | `sqltext/**/*.sql` 파일 로딩 → SQL 컴포넌트 생성 |
| **3단계** | `xml_loading.py` | MyBatis XML 파싱 → SQL 컴포넌트/JOIN 관계 생성 |
| **4단계** | `java_loading.py` | Java 클래스/메서드 추출 → `classes`/`components` 등록 |
| **4-1단계** | `sqltext_java_matcher.py` | sqltext SQL과 Java 문자열 매칭 → CALL_QUERY 관계 생성 |
| **5단계** | `backend_entry_loading.py` | Spring/Servlet API 진입점 분석 → `API_URL` 생성 |
| **6단계** | `frontend_loading.py` | 프론트엔드 API 호출 분석 → 관계 구축 |
| **7단계** | `consistency_validator.py` | DB 기반 관계 보강 + 데이터 무결성 검증 |

### 실행 순서
```
1단계 → 2단계 → 2-1단계 → 3단계 → 4단계 → 4-1단계 → 5단계 → 6단계 → 7단계
```

## 4. 핵심 개념

### FileContext 스택 관리
모든 파일 분석 시 FileContext를 push/pop하여 원본 파일 정보를 추적합니다.

```python
# 파일 분석 시작
FileContext.push_file(file_id, path, file_type, stage)

try:
    # 컴포넌트/관계 생성 시 자동으로 현재 file_id 사용
    db_utils.insert_component(...)

finally:
    # 파일 분석 종료
    FileContext.pop_file()
```

**주의사항**:
- FileContext 없이 DB 기록 시도하면 즉시 에러 발생
- push/pop은 반드시 대칭적으로 처리 (finally 블록 활용)
- 모든 컴포넌트/관계는 실제 file_id와 연결되어야 함

### INFERRED 생성 금지
과거에는 파일을 찾지 못하면 "INFERRED_*" 파일을 자동 생성했으나, **현재는 즉시 오류를 발생**시킵니다.

```python
# ❌ 과거 방식 (금지)
if not file_found:
    create_inferred_file()

# ✅ 현재 방식 (필수)
if not file_found:
    raise FileNotFoundError(f"파일을 찾을 수 없음: {file_path}")
```

### sqltext 기능
`projects/{project}/sqltext/**/*.sql` 폴더에 독립적으로 SQL 파일을 관리할 수 있습니다.

**처리 흐름**:
1. **2-1단계**: sqltext 폴더의 모든 SQL 파일을 `layer='QUERY_FROM_SQLTEXT'`로 등록
2. **4-1단계**: Java 파일 내용에서 SQL 파일명(쿼리 ID) 문자열 검색
3. **자동 매칭**: Java METHOD → sqltext SQL 간 CALL_QUERY 관계 자동 생성

**사용 예시**:
```
projects/sampleSrc/sqltext/user/getUserList.sql  (파일명 = 쿼리 ID)
→ Java 파일 내 "getUserList" 문자열 검색
→ CALL_QUERY 관계 자동 생성
```

### 듀얼 DB 아키텍처
- **metadata.db**: 컴포넌트, 관계, 테이블 스키마 등 메타데이터 저장 (SQLite)
- **SqlContent.db**: SQL 쿼리 본문을 gzip 압축하여 저장 (성능 최적화)

## 8. 실행/디버깅 팁

### 로그 확인
- **로그 위치**: `logs/SourceAnalyzer_*.log`
- **상세 로그**: `--verbose` 플래그 사용 시 DEBUG 레벨 출력
- **에러 추적**: `handle_error()` 호출 시 스택 트레이스 자동 기록

### 일반적인 오류와 해결

**오류 1**: "현재 파일 컨텍스트가 설정되지 않았습니다"
- **원인**: FileContext push 누락
- **해결**: 해당 파서/로더에서 `push_file()` 호출 확인

**오류 2**: "파일을 찾을 수 없음: ..."
- **원인**: 경로 불일치 또는 파일 누락
- **해결**: 파일 경로 정규화 확인, 원본 소스 존재 여부 확인

**오류 3**: "INFERRED 파일 생성 시도"
- **원인**: 과거 로직 잔재
- **해결**: 즉시 예외 발생하도록 수정 (INFERRED 생성 금지)

### 성능 최적화
- **대용량 프로젝트**: `--clear-metadb` 사용 전 백업
- **메모리 절약**: SqlContent.db gzip 압축 활용
- **병렬 처리**: 향후 개선 예정 (현재는 순차 처리)

## 10. 자주 묻는 질문

**Q1. sqltext 폴더는 어떻게 사용하나요?**
- `projects/{project}/sqltext/**/*.sql` 폴더에 SQL 파일을 배치하면 자동으로 로딩됩니다.
- 파일명이 쿼리 ID가 되며, Java 파일 내 문자열 매칭으로 자동 연결됩니다.

**Q2. 메타DB를 초기화하려면?**
- `--clear-metadb` 플래그 사용 또는 `metadata.db`, `SqlContent.db` 파일 직접 삭제

**Q3. 리포트가 생성되지 않아요**
- 메타DB가 먼저 생성되어 있어야 합니다 (`python main.py` 실행 필수)
- `--verbose`로 상세 로그 확인

**Q4. 경로 구분자가 다르게 나와요**
- 모든 경로는 `PathUtils().normalize_path_separator(..., 'unix')`로 정규화됩니다 (항상 `/`)

**Q5. 개발 중 테스트는 어떻게 하나요?**
- `pytest temp` 명령으로 회귀 테스트 실행
- 새로운 기능 추가 시 테스트 케이스 작성 권장
