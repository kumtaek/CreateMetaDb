# 전역 컨텍스트 및 파일 출처 관리 가이드

## 1. 목적
- 분석 단계 전반에서 **실제 파일 출처를 잃지 않고** 모든 메타데이터에 연결하기 위함.
- 이전의 **inferred 파일 대체** 관행을 폐기하고, 컨텍스트가 없으면 즉시 종료하도록 설계.

## 2. FileContext 개념
- 위치: `util/file_context.py`
- 관리 정보:
  - `project_id`, `project_name`
  - `file_id`, `file_path`, `file_name`, `file_type`(xml/java/jsp/js 등)
  - `stage`(xml_loading/java_loading/frontend_loading 등)
  - `component_hint`(필요 시)
- 동작 방식: **스택 구조**
  - `push_file(...)`로 현재 처리 파일을 등록
  - `current_file()`로 현재 컨텍스트 조회
  - `require_current_file()`로 미설정 시 예외 발생
  - `pop_file()`로 처리 종료 시 정리 (항상 `finally`에서 호출)

## 3. 적용 위치
- **파일 단위 push/pop**
  - `xml_loading.py`: XML 파일 처리 시작/종료
  - `java_loading.py`: Java 파일 처리 시작/종료, SQL 수집 루프에서 file_id 재사용
  - `frontend_loading.py`: JSP/JS/TS 등 프론트 파일 처리
  - (확장 시) 백엔드 엔트리, 리포트 생성 등 모든 파일 기반 로더
- **저장/분석 로직에서 컨텍스트 강제**
  - `util/sql_content_manager.py`: SQL 저장 시 컨텍스트 필수
  - `util/database_utils.py`: 컴포넌트/관계 저장 시 컨텍스트 필수
  - `parser/common_sql_analyzer.py`, `util/common_sql_processor.py`: 테이블/컬럼/관계 생성 시 컨텍스트 필수

## 4. 운영 원칙
- **컨텍스트 누락 = 즉시 오류**  
  - "현재 파일 컨텍스트가 설정되지 않았습니다" 메시지와 함께 종료되며, 원인 파일을 찾도록 유도.
- **inferred 파일 생성 금지**  
  - 파일을 찾지 못하면 예외를 발생시키고 근본 원인을 수정한다.
- **cross-platform 경로**  
  - `PathUtils().normalize_path_separator(..., 'unix')`로 `/` 일관 유지.
- **멱등 DB 기록**  
  - `INSERT OR IGNORE` / `INSERT OR REPLACE` 사용, `file_id` 필수.

## 5. 신규 코드 작성 체크리스트
- [ ] 파일을 읽기 시작할 때 `push_file` 호출 후 로깅.
- [ ] DB/관계 저장 전에 `require_current_file()`로 방어.
- [ ] 예외 발생 여부와 관계없이 `finally`에서 `pop_file()` 호출.
- [ ] 함수/모듈 주석에 컨텍스트 요구사항 명시(한글).
- [ ] 하드코딩된 임시 파일명/타입 사용 금지.

## 6. 디버깅 절차
1. 로그에서 "컨텍스트" 오류 위치 확인.
2. 해당 파일을 처리하는 로더에 `push_file` 누락 여부 확인.
3. 파일 스캔(1단계)에서 `file_id`가 등록되었는지 DB 확인.
4. 필요 시 스택 덤프(`FileContext.debug_dump()`)로 현 컨텍스트 확인.

## 7. 유지보수 팁
- 공통 유틸에 기능을 추가할 때는 기존 함수 중복을 피하고 재사용한다.
- 컨텍스트 정보는 분석 전 구간에서 공유되므로, 전역 상태 변경 시 영향 범위를 문서화한다.
