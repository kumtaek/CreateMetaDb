# 정답지(기준선) 보완본

본 문서는 SampleSrc 분석 결과 검증 기준과 반복 중단 조건을 정의합니다. 자동 개선 루프는 본 기준을 충족할 때 종료됩니다.

검증·중단 기준
- 누락 허용치: 정답지 대비 누락 0건(필수)
- 초과 허용치: 정답지 수치 대비 +10% 미만까지 OK, +10% 이상이면 오탐/중복으로 간주하여 재개선
- 반복 한도: 최대 3회 자동 개선 후에도 미달이면 수동 점검 대상으로 종료
- 주요 지표: API_URL→METHOD, METHOD→SQL, SQL→TABLE 관계수, JOIN 건수, 컬럼 추출 건수, 총 SQL 수

수작업 기준선 작성 가이드(샘플)
- 범위: `projects/SampleSrc/src` 하위 Controller/DAO/Mapper XML/JPA Repository, 주요 JSP(프론트)
- 방법: 파일별로
  - API 엔드포인트 수(HTTP+경로), 컨트롤러 메서드 수
  - Mapper XML의 쿼리 수(namespace.id)
  - 각 쿼리의 테이블 수, JOIN 수, 대표 컬럼 수(SELECT/WHERE/ON에서 확인)
- 동적 테이블 표기: `users_%s` → `users_{env}` 등 템플릿 그대로 기록

판정 로직(자동화 시 참고)
- 지표별로 (실제값 vs 정답지)를 비교하여 누락=0, 초과<10%이면 통과 처리
- 불일치 항목은 로그에 패턴 요약을 남기고 규칙을 보강한 뒤 재실행

주의
- 본 문서는 기준 정의서로, 상세 정답 수치는 별도 표/CSV로 관리 가능
- 정답치 갱신 시 위의 판정 기준은 그대로 유지하세요

### 쿼리별 테이블/JOIN/대표 컬럼(발췌)

- UserMapper.findUsers (Oracle 암시적 조인)
  - FROM: USERS u, DEPARTMENTS d, USER_PROFILES p
  - JOIN: u.DEPT_ID = d.DEPT_ID, u.USER_ID = p.USER_ID(+)
  - SELECT 대표 컬럼: u.USER_ID, u.USER_NAME, d.DEPT_NAME, p.PROFILE_IMAGE_URL

- UserMapper.findUsersWithAnsiJoin (ANSI 조인)
  - FROM: USERS u INNER JOIN DEPARTMENTS d ON u.DEPT_ID=d.DEPT_ID LEFT JOIN USER_PROFILES p ON u.USER_ID=p.USER_ID
  - JOIN: INNER(USERS–DEPARTMENTS), LEFT(USERS–USER_PROFILES)
  - SELECT 대표 컬럼: u.USER_ID, u.USER_NAME, d.DEPT_NAME, p.PROFILE_IMAGE_URL

- ImplicitJoinMapper.selectUsersWithOrderDetails (암시적 복수 조인)
  - FROM: users u, orders o, order_items oi, products p
  - JOIN: u.user_id=o.user_id, o.order_id=oi.order_id, oi.product_id=p.product_id
  - SELECT 대표 컬럼: u.user_id, u.username, p.product_name

- MergeQueryMapper.mergeUserStatistics (MERGE)
  - USING: users u LEFT JOIN orders o ON u.user_id=o.user_id
  - ON: us.user_id=src.user_id
    - 대표 컬럼/집계: COUNT(o.order_id), SUM(o.total_amount), MAX(o.order_date)

- ProductMapper.analyzeProductSalesPerformance
  - FROM: products p
    INNER JOIN order_items oi ON p.product_id = oi.product_id
    INNER JOIN orders o ON oi.order_id = o.order_id
    LEFT JOIN categories c ON p.category_id = c.category_id
    LEFT JOIN brands b ON p.brand_id = b.brand_id
  - SELECT 대표 집계: COUNT(DISTINCT oi.order_id), SUM(oi.quantity), SUM(oi.quantity*oi.unit_price)

- UserManagementMapper.selectUserById
  - FROM: users u LEFT JOIN user_profiles up ON u.user_id=up.user_id
  - SELECT 대표 컬럼: u.*, up.first_name, up.phone

- UserMapper.findUsersWithOrderInfo
  - FROM: users u LEFT JOIN orders o ON u.user_id=o.user_id
  - SELECT 대표 집계: COUNT(o.order_id), SUM(o.total_amount), MAX(o.created_date)

### 기준선 수치(초안)

- SQL 총수(sql_total): 200± (현재 210 관측)
- JOIN 합계: 15± (EXPLICIT/IMPLICIT 합)
- USE_TABLE: 100±
- CALL_QUERY: 70± (mapper_map 미사용 시 다소 하락 가능)
- CALL_METHOD: 110± (controller_api_map 기반)
- USE_COLUMN: 50± (즉시/배치 반영 기준)

비고: 위 수치는 초안이며, `ProductMapper.xml`, `UserManagementMapper.xml`, `resources/mybatis/mapper/UserMapper.xml`의 상세 id 반영 후 보정 예정.
